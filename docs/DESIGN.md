# 設計思想

この文書は、Poker GTO の画面と操作を決めるときの拠り所。新しい画面や機能を足すときは、まずここに照らして考える。

目指すのは「操作しやすくて、見やすくて、続けたくなる」学習ツール。ポーカーのゲームクライアントの文法を借り、学習ツールとしての答え（GTO）を、遊んでいる手の流れを止めずに見せる。

## 1. 入り口は3つだけ

| 入り口 | ユーザーがしたいこと |
|---|---|
| 分析 | 実際にあったハンドを卓に入れて、GTO ならどうするかを知る |
| 壁打ち | GTO を相手に判断して、採点と理由をもらう |
| 教材 | 考え方を読んで、数字を変えて確かめる |

機能を足すときは、この3つのどこに入るかを先に決める。トップレベルの入り口は増やさない。

## 2. 卓がすべての操作の場所

- **席・手札・ボード・アクション・計算は、すべて卓の上で行う。** 卓から離れたフォームで入力させない
- 自分の席は常に手前（下）。行動は時計回りに進み、手番の席を光らせる
- 手番の人の操作ボタンは卓のすぐ下に一列に並べる。よく使う Fold・Call・Raise を同じ位置に置き、キーボードでも押せるようにする（F / C / R、または 1〜4）
- ストリートが終わったら、各席の前のチップはポットに集める。ポットは卓の中央に置く
- フロップ・ターン・リバーのカードは、卓の中央の空いた枠をクリックして選ぶ

## 3. 次にやることは常に1つだけ

- 卓の上に「いま何をすればよいか」を1行で出す（例: 「CO の番です。実際に起きたアクションを選んでください」）
- 主ボタン（明るい塗り）は、その場面で押すべきボタン1つだけにする
- 詳しい設定は初期値で動くようにして、折りたたみの中に入れる。最初の1手から答えにたどり着けることを優先する

## 4. 答えは手元に、詳しさは段階的に

- GTO の答えは、操作ボタンの隣の「GTO の答え」に大きく出す。自分の手札が分かっていれば、その手札で何をどれだけ選ぶかを最初に見せる
- レンジ表・EV・EQ・レンジの構成などの詳しい情報は、卓の下に置き、見たい人が見に行く
- 頻度を隠して自分で考えたいときのために、答えは隠せるようにする

## 5. 操作には手応えを返す

- 押したアクションは、すぐ卓の上（席の下のラベル、前に出たチップ、ポット）に反映する
- 計算中は卓の中央に進み具合を出し、途中の結果で先に進めるようにする
- 動きは控えめにし、情報を隠さない。`prefers-reduced-motion` では動きを止める

## 6. 続けたくなる仕組み

- 壁打ちでは、連続正解・正答率・今日の問題数を常に見せる
- 間違えたときは責めずに、なぜ別のアクションが良いのかを数字で説明し、すぐ次に進めるようにする
- 区切り（10問ごとなど）でまとめを見せ、次の目標を置く

## 7. 読みやすさ（教材）

- 本文は 16px 以上、行間は 1.9 前後、1行は全角 40 字程度まで
- 章の冒頭に「この章で分かること」を3点以内で置き、結論から書く
- 式や数字は「例題」の囲みで、具体的な数字と一緒に見せる
- 章の最後に確認問題を置き、すぐに答え合わせできるようにする
- 前後の章へ移動するボタンと、読み終えた章の印を置く

## 8. 見た目

- 黒基調。面は無彩色の濃淡で分け、選択中は明るさで示す
- 色を持つのは、アクション（赤 = ベット・レイズ、緑 = チェック・コール、青 = フォールド）とスートだけ
- 装飾のための色や枠は使わない。区切りは 1px の罫線
